Hearing result response fidelity

POST /hearing/result returns placeholder content where the ticket's sample response carries request-derived defendant identity and richer seeded entity data. Three phases: make the seed authoritative, echo the posted defendant details, then lock every request/response pair behind a fixture-driven IT harness.

0

Root cause (established, not assumed)

Verified
Reproduced against the running simulator; the live body matches the reported one byte for byte apart from the timestamp. The response is assembled only from field-paths.yaml rows that a posted result code selects, plus the baseline: true floor for each requested root. Two independent defects follow.
  • D1 — the seed can only override, never introduce. ValueResolver is consulted per catalogue row, so a path with no row is unreachable regardless of seed content. Proof: the bundled seed already carries a defAddress that never reaches the response.
  • D2 — the posted request body is discarded. NowsDataItemsAssembler.assemble() receives only (caseUrn, resultCodes, requestedNames); defendantDetails never reaches assembly, yet eight fields of the ticket's sample response are exact echoes of it.
  • Decisive constraint. The sample response carries three impositions. Catalogue rows are pinned to imposition[0], so adding catalogue rows cannot express imposition[1..2] — extending the catalogue alone is structurally incapable of closing the gap.
Agreed at gate: request echo > seed > catalogue default

Make the seed authoritative for a requested entity

D1
Revised during build (v2). The seed subtree is merged after the three existing passes and fills gaps only. The v1 plan had it overwrite, to reproduce the sample response's bare 340; that would have broken AC4 ("amounts numeric with 2 decimal places") by replacing ValueResolver's coerced scale with whatever the seed file was authored at. Overwriting also buys nothing: for any path a catalogue row covers, ValueResolver has already read the same seed. The three existing passes are untouched.
  • Merge only requested roots — an unrequested entity must stay absent (protects returns_exactly_the_requested_entities_and_nothing_more)
  • Element-wise array merge, so a seed may supply N impositions / offences
  • Unknown seed keys keep failing loudly at convertValue — no silent drop
  • Populate the seed for the ticket's case: offence detail, the imposition set, imposing court, account notes, days in default, account date imposed
  • AC4 (found during build). An amount the seed alone contributes bypasses ValueResolver entirely. SeedStore now parses with USE_BIG_DECIMAL_FOR_FLOATS + withExactBigDecimals(true) — without the second, Jackson's node factory strips the trailing zeros and undoes the first — so the seed file's scale is authoritative, and a guard test fails the build if any amount reaches the wire at another scale.
A new case becomes a data edit, not a code change

Echo the posted defendant details

D2
A new, single-purpose mapper derives an overlay from defendantDetails and applies it last, with overwrite, and only for roots the caller requested. Highest precedence by design: the caller's own payload beats both seed and catalogue default, so a new test pair with a different defendant needs no seed edit.
  • Field mapping (names only — no values recorded here): forename+surname→defName, dateOfBirth→DoB (reformatted to dd MMM yyyy), nationalInsuranceNumber, homeTelephoneNumber→homeTelNo, mobileTelephoneNumber→mobileTelNo, address1..3+postcode→defAddress.*, prosecutorDefendantId→accountNumber
  • Absent optional field ⇒ no overlay entry, so the seed still supplies it (homeTelNo is the live example of this)
  • Update HearingResultControllerIT: accountNumber now echoes the posted id instead of the catalogue default — the assertion is changed to the new truth, never deleted

Fixture-pair IT harness

mandated
Every request/response pair gets a test, and adding a pair must stay a drop-in. A parameterised IT discovers each directory under the fixtures root and asserts the real response against the recorded one.
  • <fixture>/request.json + <fixture>/expected-response.json; a new pair is a new folder, no Java edit
  • Strict whole-body comparison, timestamp excluded — it is Instant.now() by decision, and nothing in the request supplies a time of day
  • Numeric comparison by value, so a recorded 340 matches an emitted 340.00 (the money scale is deliberate)
  • correlationId present in the expected body ⇒ sent as X-Correlation-ID, keeping each fixture self-describing
  • conformsToSpec() on every pair, so no fixture can encode a contract-invalid response
  • AC4 guard asserts every amount on the wire at 2dp — checked against the raw response TEXT, since every JSON parser in the path destroys scale by default
Green suite via ./gradlew :gob-simulator:test before review

Open questions carried to the gate

review
  • Timestamp. The ticket's sample shows the hearing date at a fixed time of day; the endpoint emits the current instant. Treated as a captured moment, not a rule — flagged rather than guessed.
  • Fixture data. The pair is synthetic simulator data, consistent with the existing fixtures, but it is defendant-shaped. Confirm it is cleared for commit before the fixtures land.
  • Design spec drift. §5 describes content as label-driven only. Seed-as-floor and the request echo widen that; if accepted, §5 and ADR coverage need the same edit. The simulator README is updated.
  • AC4/AC8 vs the sample response. Echoing prosecutorDefendantId into accountNumber follows the ticket's sample, but AC8 names the unseeded default for Account No. and AC4 declares it A(7), which a prosecutor defendant id exceeds. The contract puts no pattern on the property, so conformance cannot adjudicate. For the BA.
