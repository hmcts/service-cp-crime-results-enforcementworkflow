Implementation Plan · CIMD-4372

Bearer token enforcement on hearing endpoints

Require an AuthController-issued, unexpired bearer token on POST /hearing and POST /hearing/result, closing the gap between the bundled v0.4.0 contract (which declares both endpoints ClientCredentials-secured) and the simulator, which today validates nothing.

Production code

4 new · 2 changed
A HandlerInterceptor, not a servlet filter: a filter runs ahead of @RestControllerAdvice and would have to hand-serialise its own JSON, while an interceptor's exception flows through the existing GlobalExceptionHandler and picks up the contract's ErrorResponse shape from the same path as every other error. No spring-boot-starter-security — that starter secures everything by default and would need CSRF and form-login switched off, more configuration than the feature itself.
  • TokenStore — ConcurrentHashMap<String, Instant> of token→expiry, injected Clock so expiry is testable without sleeping

  • UnauthorizedException + BearerTokenInterceptor
  • SecurityConfiguration registers the interceptor on /hearing and /hearing/result only — /auth/token stays open
  • GlobalExceptionHandler gains a 401 handler, wording taken from the contract's Unauthorized response
