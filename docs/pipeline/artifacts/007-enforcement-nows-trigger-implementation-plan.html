Triggering NOWS generation for enforcement hearings

The results-processing Function App (FA) stays the entry point: it creates the NOW requests in hearing-nows (H), gives every enforcement NOW a request id (held in WAITING_FOR_GOB) and notifies the enforcement workflow (W). W reads the share's results, sends each offence to GOB once (first-time shares only; an amend & reshare is never sent), and publishes GOB's data with the request ids as a public event on Artemis. H matches on request id and resumes generation. Retries via cp-task-manager; no message is lost.

How it works

hearing-resulted → FA: build NOWs; enforcement NOW → requestId (uuid) → POST H add-now-document → WAITING_FOR_GOB
                   FA → POST W /enforcement-notifications {hearingId, hearingDate, nows[requestId, masterDefendantId]} → 202
W stage 1 (task): results (cache by day → Results API) → select → offences not yet sent → GOB via gateway → SUBMITTED
                   (all already sent → SKIPPED_NOTHING_NEW, reuse GOB data; no recognised code → nothing published)
W stage 2 (task): public.enforcementworkflow.enforcement-nows-data-ready {nows, accountNumber, nowsDataItems} → PUBLISHED
H: per requestId → NOW in WAITING_FOR_GOB → enfNowsDataItems + account → ENFORCEMENT_DATA_ADDED → existing chain
     no NOW yet → keep data by requestId (retention) → complete the NOW when it arrives
failures: 3 retries with back-off per stage → STORED_FAILURE → automatic replay schedule / manual replay; unknown GOB outcome → manual only

Decisions this plan rests on

  • Request id per enforcement NOW, created by FA (R4); H holds them with its existing WAITING_FOR_GOB routing
  • Reshare never sent; first-time share once per offence (R9); submission key = notification + case + defendant; gob_sent_offence keeps once-per-offence
  • Internal network + system-user allow-list (R2); one contract repo for all enforcement APIs (R3)
  • Redis via Entra ID only, switched off until the platform enables it (R8); Results latest day accepted for now (OP-1)
  • Product decisions 2026-10-22: every result code sent to GOB (only no code or a code over 10 characters left out); amend & reshare never sent (isReshare from the notification), earlier GOB data reused or NO_GOB_DATA; held NOWS wait without time limit; email on amend & reshare is its own story; NOW distribution by the existing subscription rules (FR-021, T088)
  • Decided 2026-10-23: a reshare without earlier GOB data waits while the hearing's first-time share is still received, processing or a stored failure (retry, then STORED_FAILURE with FIRST_SHARE_IN_PROGRESS; T091)
  • Temporary exception 2026-10-23: TEMP payload diagnostics in W and H for QA, test environments with synthetic data only; removed before main (research I19, T090)
  • Public event with GOB data — ADR specs/001-…/adrs/002-CIMD-4530-… must be Accepted before production
