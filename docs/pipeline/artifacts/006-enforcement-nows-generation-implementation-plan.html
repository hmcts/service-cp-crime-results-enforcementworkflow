Enforcement NOWS generated with GOB account data

After GOB (Libra) accepts an Enforcement case's results, the enforcement workflow (W) hands GOB's account data to hearing-nows (H) through a new enforcement-specific command. Common Platform's existing NOWS flow (the NOWS Function App, unchanged) still decides and builds the NOWS. The two flows meet in H, in either order, and each NOW is completed once with its own GOB data before the existing generate → store → distribute chain. W also sends each offence's final result to GOB once, so a later hearing day of the same hearing is now sent too.

How the flows meet

hearing-resulted ─┬─W: select → correlationId = UUID(hearingId|hearingDay) → drop offences already sent / adjourned
                  │     → GOB (via gateway) → SUCCEEDED → POST H /enforcement-nows-data (202) → HANDED_OVER
                  │     (nothing new or reshare → no GOB call; hand over the latest GOB data, gobDataReused=true)
                  └─NOWS Function App (unchanged): decide NOWS → POST H add-now-document (per NOW)

H, Enforcement-case NOW (toggle on): WAITING_FOR_ENFORCEMENT_DATA, key = (UUID(hearingId|orderDate), masterDefendantId)
   kept data present → complete once (conditional update) → enfNowsDataItems → existing chain
   absent            → wait; max wait passes → FAILED "no GOB data"
H, hand-over: keep/replace by sharedTime → complete waiting NOWs of the key → release after retention
